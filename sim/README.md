# شبیه‌ساز سلول دیجیتال — نسخهٔ ۰٫۱

این بسته یک شبیه‌ساز دوبعدی قابل اجرا برای آزمایش برخوردها و ثبت تجربهٔ سلول دیجیتال فراهم می‌کند. موتور دینامیک اجسام صلب بر پایهٔ Pymunk/Chipmunk2D است؛ از انیمیشن ساده یا بازتاب دستی سرعت به‌جای حل‌گر برخورد استفاده نشده است.

## دامنه و فرض‌های مدل

- مستطیل صلب در مرکز مختصات، با سرعت زاویه‌ای ثابت ساعت‌گرد.
- یک سلول دایره‌ای ثابت در مرکز جهان.
- میله‌های صلب دارای جرم، ممان اینرسی، حرکت انتقالی و دوران مستقل.
- میله‌ها با میله‌های دیگر، سلول و دیواره تماس فیزیکی دارند.
- برخوردها با کشسانی و اصطکاک قابل تنظیم حل می‌شوند؛ مقادیر پیش‌فرض کشسانی ۱ و اصطکاک صفر است.
- ضخامت میله‌ها و دیواره صفر نیست؛ این موضوع از ابهام هندسی پاره‌خط‌های بدون ضخامت جلوگیری می‌کند.
- زمان شبیه‌سازی، حالت اجسام و رویدادهای برخورد ثبت می‌شوند.
- حسگر پایهٔ سلول فقط زمان برخورد و طول میله را در اختیار تحلیل‌گر رویداد قرار می‌دهد؛ پیش‌بینی‌کننده به حالت پنهان اجسام دسترسی ندارد.

### محدودیت هندسی طول‌ها

با تنظیمات پیش‌فرض، طول هر میله از min_rod_length تا max_rod_length است و قید زیر برقرار است:

`max_rod_length <= min(width, height) / 6`

همچنین، اگر enforce_total_length_constraint=True باشد، مجموع طول میله‌ها به مقدار میانی فاصلهٔ سطح سلول تا دیواره‌های نزدیک و دور تنظیم می‌شود:

`target_total_length = (min(width, height) + max(width, height)) / 4 - cell_radius`

این قید از تفسیر عملیاتی «مجموع طول خطوط بین کمترین و بیشترین فاصلهٔ سلول تا دیواره» استفاده می‌کند. اگر تعداد میله‌ها و بازهٔ طول نتوانند این مجموع را تأمین کنند، پیکربندی رد می‌شود؛ سامانه به‌جای نقض خاموش قید، خطا می‌دهد.

## نصب

Python 3.10 یا بالاتر لازم است.

```bash
cd sim
python -m venv .venv
# Linux/macOS
source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -e ".[test]"
```

## اجرا

اجرای پیش‌فرض برای ۳۰ ثانیه:

```bash
digital-cell-sim --duration 30 --output runs/baseline
```

یا بدون نصب فرمان:

```bash
python -m digital_cell_sim.cli --duration 30 --output runs/baseline
```

نمونه با تغییر پارامترها:

```bash
python -m digital_cell_sim.cli \
  --duration 60 \
  --rods 8 \
  --omega 0.35 \
  --width 12 \
  --height 10 \
  --max-length 1.2 \
  --dt 0.0083333333 \
  --output runs/omega_035
```

برای تغییر تعداد میله‌ها باید همچنان قید مجموع طول و حد طول هر میله برقرار باشد. اگر تعداد میله‌ها زیاد شود و پیکربندی از نظر هندسی قابل جاگذاری نباشد، برنامه خطای مشخص می‌دهد.

## خروجی‌ها

- config.json: پارامترهای دقیق اجرا و seed.
- snapshot.json: وضعیت نهایی مستطیل، سلول و تمام میله‌ها.
- collision_events.json: رویدادهای برخورد با سلول.
- collision_events.csv: همان رویدادها در قالب CSV.
- prediction_metrics.json: خطای پیش‌بینی‌های خط مبنا.
- run_summary.json: خلاصهٔ اجرا و معیارهای اصلی.

## آزمون‌ها

```bash
python -m unittest discover -s tests -v
```

آزمون‌ها شامل هندسهٔ فاصلهٔ پاره‌خط‌ها، اعتبارسنجی قید طول، محدودبودن وضعیت عددی، ثبت برخورد سلول، بازتولید شرایط اولیه با seed ثابت، و جلوگیری از نشت رویداد آینده به پیش‌بینی است.

## برخوردها و تضمین‌های عددی

حل‌گر Pymunk برخوردها را با مدل اجسام صلب حل می‌کند. گام زمانی به زیرگام‌های تطبیقی تقسیم می‌شود تا جابه‌جایی بیشینهٔ نقطهٔ تماس نسبت به کوچک‌ترین ویژگی هندسی محدود بماند. اگر تعداد زیرگام لازم از max_substeps فراتر رود، اجرا متوقف و خطای روشن صادر می‌شود؛ این وضعیت به‌صورت بی‌صدا نادیده گرفته نمی‌شود.

بااین‌حال، زیرگام‌گذاری تطبیقی **اثبات ریاضی عدم عبور در همهٔ سرعت‌ها و همهٔ شرایط نیست** و این نسخه یک حل‌گر اختصاصی CCD دقیق برای میله‌های در حال دوران نیست. برای ادعای اعتبارسنجی کامل باید آزمون‌های تنش، همگرایی با گام زمانی، خطای انرژی و برخوردهای نزدیک به مماس روی محیط اجرا شوند. همچنین دیوارهٔ چرخان می‌تواند به اجسام انرژی بدهد؛ بنابراین ثابت‌بودن انرژی کل در این حالت انتظار درستی نیست.

## یادگیری و معیارها

evaluate_online_baselines پیش‌بینی یک‌گام‌به‌جلو را بر اساس میانهٔ فاصله‌های زمانی قبلی و میانهٔ طول‌های مشاهده‌شده ارزیابی می‌کند. رویداد فعلی قبل از پیش‌بینی وارد تاریخچه نمی‌شود. این روش تنها خط مبناست؛ بهبود نسبت به آن، به‌تنهایی، شاهد AGI یا کشف ریاضی نیست.

برای ادعای یادگیری باید چند seed مستقل، مجموعهٔ آزمون جدا، مقایسه با خط مبنا و گزارش عدم‌قطعیت اجرا شوند. وضعیت پنهان شبیه‌ساز فقط برای ارزیابی استفاده می‌شود و نباید به ورودی پیش‌بینی‌کننده نشت کند.

## وضعیت اعتبارسنجی

این شاخه کد و آزمون‌های رگرسیون را تعریف می‌کند. تا زمانی که اجرای CI و آزمون‌های تنش روی نسخهٔ نهایی موفق نشده باشند، نباید آن را «بدون خطا» یا «از نظر فیزیکی کاملاً اعتبارسنجی‌شده» توصیف کرد.

## آزمایش چندبذری و مقایسهٔ سرعت چرخش

پس از نصب بسته، اجرای آزمایش مقایسه‌ای با seedهای یکسان برای محیط ثابت و چند سرعت چرخش:

```bash
python experiments/run_sweep.py --duration 20 --replicates 5 --omegas 0.0 0.25 0.5 --rods 8 --output runs/sweep
```

خروجی شامل دادهٔ هر اجرا در CSV و آمار توصیفی در JSON است. این آزمایش برای مقایسهٔ قابل تکرار شرایط محیطی طراحی شده است و به‌تنهایی آشوب یا یادگیری را اثبات نمی‌کند.


## شرایط اولیهٔ تصادفی و بازتولیدپذیری

- در اجرای عادی، اگر `--seed` تعیین نشود، هر ساخت شبیه‌سازی یک seed تصادفی ۱۲۸بیتی تازه دریافت می‌کند؛ بنابراین موقعیت، زاویه، طول‌های مجاز، سرعت انتقالی و سرعت زاویه‌ای میله‌ها در هر اجرا دوباره نمونه‌گیری می‌شوند.
- مقدار `effective_seed` در `config.json`, `snapshot.json` و خلاصهٔ اجرا ذخیره می‌شود تا همان اجرا قابل بازتولید باشد.
- برای بازتولید دقیق یک اجرا، seed ثبت‌شده را به `--seed` بده.
- آزمایش sweep به‌طور پیش‌فرض برای هر تکرار و هر سرعت چرخش seed متفاوت تولید می‌کند.
- برای آزمایش کنترل‌شده‌ای که اثر سرعت چرخش را با شرایط اولیهٔ یکسان مقایسه می‌کند، صریحاً `--paired-seeds` را فعال کن. این حالت عمداً شرایط اولیهٔ هر تکرار را بین سرعت‌های مختلف مشترک نگه می‌دارد؛ تکرارهای مختلف همچنان شرایط اولیهٔ متفاوت دارند.
- اگر `--seed` برای sweep تعیین شود، تولید seedها برای کل sweep بازتولیدپذیر می‌شود؛ در غیر این صورت seedهای جدید از منبع تصادفی سیستم گرفته می‌شوند.
