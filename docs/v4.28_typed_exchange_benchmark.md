# ECF v4.28 — Typed Exchange with Receiver-Side Revalidation

## Research question

Does neighbor-only or randomized peer exchange improve held-out performance when every received hypothesis must pass receiver-local validation and all conditions have the same maximum candidate-validation budget?

Implementation: `src/flf_ecf/v428.py`; runner: `scripts/run_v428_typed_exchange_experiment.py`; tests: `tests/test_v428.py`.

## Conditions

- `isolated`: each cell can validate only its own proposals.
- `neighbor_exchange`: each cell can also receive top-ranked proposals from two ring neighbors.
- `randomized_exchange`: each cell receives the same number of peer sources sampled without ring adjacency.

Each condition uses the same per-cell maximum number of candidate validations. Candidate proposals are typed v4.27 messages; receiver validation uses only receiver-local observations. Sender observations are retained as provenance but are not counted as receiver validation.

## Adversarial and robustness scenarios

- `clean`: ordinary independent sender training samples.
- `false_claims`: a subset of messages contains a deliberately incorrect threshold and fabricated sender observations designed to make the claim look perfect. The receiver must re-evaluate it locally.
- `correlated_evidence`: all cells share the same sender-side training observations, modeling evidence dependence; receiver validation sets remain local.
- `distribution_shift`: validation uses the source threshold, while the held-out test environment changes to a different threshold. This measures how quickly apparently valid relations can fail under shift.

## Metrics

The report includes end-to-end held-out accuracy (an abstention/no accepted candidate counts as zero task success), selection coverage, held-out accuracy conditional on selecting a candidate, validation accuracy, threshold error, accepted candidate count, false candidates rejected, compute-accounting units, and received bytes. These separate coverage from quality so an arm cannot look strong merely by solving a small subset, or look weak solely because it abstains more often. Seeds are deterministic. The experiment runner preserves full raw trial records as JSON.

## Interpretation limits

This is a synthetic, threshold-based experiment with a known oracle and a human-specified candidate grid. It tests message handling and a narrow transfer protocol, not self-created mathematics, unrestricted learning, or AGI. Receiver-local validation is only as reliable as its sampling design; a finite pass is not a universal proof. Compute and energy figures are deterministic policy accounting, not hardware measurements.
