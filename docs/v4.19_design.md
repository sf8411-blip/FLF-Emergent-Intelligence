# ECF v4.19 — Builder-Language Genesis

## Research question
Can the system expand a deliberately incomplete representation-builder language by proposing a new operator composition, then retain it only when it produces a reproducible improvement on held-out data?

This is a bounded prototype, not unrestricted self-modifying code, general intelligence, or evidence that mathematics can emerge without inductive bias.

## Protected baseline
The v4.18.5 files and results remain unchanged. All v4.19 work is isolated in branch `v4.19-builder-language-genesis`; v4.18 regression tests remain part of CI.

## Mechanism
1. Start with an intentionally incomplete language containing raw feature access only.
2. Propose candidate expressions from an explicit primitive vocabulary: addition, multiplication, sine, absolute value, and square.
3. Interpret expression trees using a whitelist evaluator. Never execute generated Python or shell code.
4. Fit the same linear readout for the baseline language and the language augmented by one candidate.
5. Compare both on held-out validation data.
6. Promote only if relative RMSE gain reaches the configurable threshold; otherwise preserve the prior language.
7. Record candidate, scores, gain, and rejection reason in the experiment harness before expanding the search.

## Prototype contract
`src/flf_ecf/v419.py` contains expression trees, safe evaluation, deterministic proposal generation, held-out validation, and pure promotion logic. Unit tests cover composition, non-finite input rejection, rejection of unhelpful candidates, and held-out acceptance of a missing square feature.

The default 2% gain threshold is configurable and is not a claim of statistical significance. This prototype does not yet perform repeated-seed significance testing, transfer testing, or shuffled/noise controls; those are required before claiming a full v4.19 research gate.

## Full acceptance gates
- **G1 — Reproducibility:** repeated independent seeds and frozen train/validation/test splits; all v4.18 regression tests pass.
- **G2 — Held-out value:** candidate improves validation performance by the preregistered margin and does not regress an untouched test set.
- **G3 — Complexity control:** report expression complexity and compute cost; reject improvements that only memorize.
- **G4 — Transfer:** a promoted operator helps on an independently generated world.
- **G5 — Negative controls:** shuffled targets and pure-noise worlds must not lead to stable operator promotion above the declared false-promotion rate.
- **G6 — Rediscovery:** independent runs recover equivalent operator behavior, not necessarily identical syntax.
- **G7 — Provenance:** store seed, split hash, candidate expression, baseline/candidate metrics, decision, and software revision.

## Limitations and next work
The primitive vocabulary is human-defined, so novelty is compositional rather than creation from nothing. The present function tests one candidate against a linear readout. Next add an experiment runner with repeated seeds, a separate untouched test set, negative controls, expression canonicalization, resource accounting, and JSONL provenance. Do not report a pass until experiments have actually run in CI or another reproducible environment.
