# ECF v4.22 — Counterexample-Directed Invariance Testing

## Purpose

v4.20 checks an expression against a supplied finite set of transformations and
sample points. v4.22 adds seeded sampling over a bounded input domain to look
for concrete witnesses that refute a proposed invariance.

For expression f and transformation T, the tested claim is:

`f(T(x)) = f(x)`

A returned counterexample is evidence against this claim under the implementation
and tolerance used. No counterexamples found means only that this finite search
did not find one; it is not a proof of invariance.

## API

`search_counterexamples(expr, transform, lower, upper, n_samples=1000,
tolerance=1e-8, max_counterexamples=5, seed=0)`

Bounds can be scalars or one-dimensional vectors matching the expression's
feature count. Sampling is uniform in the bounded box. Results include the seed,
number of points searched, maximum normalized error, and concrete input and
transformed points for each returned witness.

## Reproducibility and limitations

- A fixed seed makes the sampled points reproducible for a fixed NumPy version.
- Uniform random search can miss rare, narrow, or boundary-only counterexamples.
- The search checks only the provided transformation and domain.
- Floating-point tolerance is part of the operational claim.
- This module does not prove an identity, infer all valid transformations, or
  independently establish that the proposed mathematical statement is useful.
- For scientific claims, follow with adversarial/boundary search, symbolic
  reasoning where available, and a separate held-out domain.

## Research-loop integration

A research step can treat a found witness as negative evidence and store it in
its checkpoint history. The next step should use that witness to refine the
hypothesis or choose a different candidate. A clean finite search must not
automatically mark the hypothesis as mathematically proven.
