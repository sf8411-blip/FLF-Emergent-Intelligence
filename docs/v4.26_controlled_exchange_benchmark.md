# v4.26 — Controlled experience-exchange benchmark

## Research question

Under a fixed per-cell candidate-validation budget, does sharing candidate relations
between digital cells improve performance on held-out examples compared with
isolated cells? Does the declared ring-neighbor topology add value beyond pooling
the same number of candidates from randomly selected peers?

This is a narrow benchmark, not a demonstration of AGI or self-created mathematics.

## Synthetic world

A hidden environment defines a relation on a scalar distance:

`related(d) = (d <= target_threshold)`.

Each cell receives separate discovery, validation, and test samples. The environment
provides binary feedback to score proposed thresholds. This oracle is intentionally
limited to the synthetic benchmark; the experiment does **not** assume real-world
scientific problems provide ground-truth labels.

Each cell randomly proposes a bounded subset of a human-specified threshold grid.
Candidate experience contains the threshold, discovery score, and originating cell.
Cells share their highest-scoring candidates with ring neighbors or randomly chosen
peers. Each cell validates no more than `candidates_per_cell` candidates, chooses
using its validation split, and is scored on a separate test split.

## Conditions

1. **isolated** — each cell can validate only its own proposals.
2. **neighbor_exchange** — each cell may add proposals received from its two ring neighbors.
3. **randomized_exchange** — each cell receives proposals from the same number of randomly selected peers, not selected by ring adjacency.

All conditions reuse the same per-seed datasets and initial proposals. Candidate
validation count is capped equally across conditions. The randomized condition
tests whether the ring topology adds value beyond candidate pooling; it is not
assumed in advance to be worse.

## Metrics

- Mean test accuracy (higher is better).
- Mean absolute threshold error (lower is better).
- Mean validation accuracy.
- Mean candidate-pool size before the per-cell validation budget.
- Mean candidates actually evaluated.
- Paired test-accuracy gain against isolated cells, matched by seed and cell.\n- 95% bootstrap confidence intervals resample independent seeds as clusters, rather than treating connected cells as independent observations. Intervals are omitted when fewer than two seeds are supplied.

Use many independent seeds and report uncertainty (e.g. bootstrap confidence
intervals) before drawing strong conclusions. A positive mean alone is not enough
to establish robust benefit. Results apply only to this benchmark and candidate
family.

## Run

Install the repository requirements, then run:

```bash
python -m unittest tests.test_v426 -v
python scripts/run_v426_exchange_experiment.py --seeds 50 --output results/v4.26-exchange-benchmark.json
```

The script records the configuration, aggregate metrics, paired gains, and all
cell-level outcomes as JSON. Keep the output file with the commit and environment
details when reporting an experiment.

## Known limitations

- The relation family (Euclidean/distance threshold) and candidate grid are human-defined.
- The benchmark's oracle feedback is stronger than unsupervised real-world discovery.
- Candidate proposals are random rather than generated by a learned cell genome.
- Cells are simulated in one process; there is no real network, cryptographic identity,
  adversarial peer, persistent checkpoint, or physical-device resource measurement.
- This benchmark tests experience exchange, not the full digital-cell architecture.
