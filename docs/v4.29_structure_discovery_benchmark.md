# ECF v4.29 — Testing ways to discover and revise computational structures

## Research question

Which bounded candidate-generation policy most reliably discovers a compositional computational structure from evidence on a controlled synthetic task?

This operationalizes the design principle “discover, test, and change computational structures based on evidence.” It is a small, falsifiable benchmark, not an AGI test.

## Strategies compared

All strategies use the same human-specified expression grammar, same train/validation/test samples per seed, and same maximum number of unique candidate expressions per greedy selection round.

- **Enumeration:** deterministic simple-first enumeration.
- **Random search:** randomized candidate ordering plus random compositions.
- **Evolutionary:** a small population is ranked by training residual error and mutated.
- **Hierarchical:** simple unary expressions are prioritized before more complex expressions; this tests a tree-inspired search order, not a model of tree biology.
- **Evidence-guided:** candidates are ranked by absolute correlation with the training residual after the linear baseline.

The “quantum-inspired” label is intentionally not used: no quantum hardware or quantum algorithm is implemented. A stochastic hypothesis pool is not, by itself, quantum computation. Likewise, no method is claimed to reproduce the actual biology of trees.

## Task and ground truth

Input is a three-dimensional continuous vector. The hidden synthetic target is:

    y = x0^2 + sin(x1) + Gaussian noise

The learner receives observations, not the target formula. The grammar has human-supplied square, sin, abs, add, and mul primitives. It is therefore a test of discovering useful compositions inside a defined language, not of inventing mathematics from nothing.

Each seed uses a deterministic random split into training, validation, and held-out test sets. Candidate search and greedy term selection use training data only. Validation RMSE is reported as a diagnostic; held-out test RMSE estimates generalization. The held-out test is not used to select a strategy or candidate.

## Metrics

- held-out test RMSE;
- relative improvement over a linear-feature baseline;
- recovery rate of the two known compositional components (square(x0) and sin(x1));
- number of candidates evaluated;
- selected expression complexity.

Raw per-seed results are retained as a JSON artifact. The run should be repeated across many seeds. Differences should be accompanied by paired seed-level uncertainty estimates before claiming one strategy is superior.

## Important fairness limitation

The candidate budget bounds the number of unique proposed expressions per selection round. Greedy selection may rescore that candidate set for a second term; reported evaluation counts must therefore be interpreted as actual scoring operations, not as the unique proposal count. The strategies share this protocol, but their candidate distributions differ. This is a first comparison, not a universal ranking of search algorithms.

## What this can and cannot establish

It can compare five ways to search a small, known grammar on one controlled compositional regression task.

It cannot establish:
- universal superiority of any strategy;
- autonomous invention of a mathematical language;
- AGI or open-ended learning;
- usefulness on arbitrary physical systems;
- an advantage from quantum mechanics or tree structure as such.

A next iteration should add multiple target families, adversarial noise, distribution shift, paired bootstrap intervals, and ablations of grammar primitives. A more ambitious test should let the system propose and validate grammar extensions, with strict sandboxing and equal compute budgets.
