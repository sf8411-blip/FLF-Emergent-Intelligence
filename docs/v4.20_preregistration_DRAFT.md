# ECF v4.20 — Preregistration DRAFT

**Status:** DRAFT / DEV-only. This document is committed before the Step-3 dress rehearsal. It is not frozen preregistration and defines no frozen seeds.

**Scope stop:** Run one fresh DEV dress rehearsal, report, and stop. Do not define frozen seeds, run T2, merge to `main`, or alter the closed v4.19 A3 files.

## 1. Scientific question
v4.20 separates two hypotheses that v4.19 conflated.

### H1 — useful feature synthesis outside the L0 span
Can residual-guided synthesis propose a feature that is demonstrably outside the complete L0 linear span, survives an independent intervention challenge, and closes a material fraction of the oracle gap without false acceptance on Null/corrupted controls?

H1 is a feature-level hypothesis. Passing H1 does **not** imply recovery of the hidden operator semantics.

### H2 — bounded operator-level genesis, conditional on H1
**Evaluate H2 only if every H1 gate passes.** Among useful admitted features, does residual-guided search recover an in-world functionally equivalent operation and outperform matched random-search controls using the same grammar?

H2 is bounded to the declared v4.20 DSL/world families. A pass is not a claim of unrestricted mathematical-language genesis, general intelligence, or AGI.

## 3. Model and data splits
Each trace uses the v4.20 split: 55% train, 20% validation, 25% test.

`B0` is the complete L0 linear model, including actions. `B1` is the benchmark-only oracle extension and is never available to synthesis or candidate selection.

For ratio/statistical gates, a non-null seed is **eligible** only if its validation-split oracle gain is at least `0.05`, as required by R7. Eligibility is determined before inspecting guided/control test performance.

## 4. DSL and constants
Candidate grammar is the same grammar for guided search, B2a, B2b, and B3. No world/operator names, true hidden feature, hidden period/window/quantile, or oracle score enters candidate generation/selection.

Per-world constants are fitted by the validated shrinking-interval 1-D search over continuous ranges. The old discrete DSL grids are not used. Every learned constant costs `0.5` in MDL.

For guided search the fixed proposal score is

`score = |corr(candidate_train, B0_train_residual)| - 0.002 * mdl_cost(candidate)`

with `mdl_cost = 1 + 0.5 * number_of_learned_constants` for the v4.20 Program representation. The `0.002` coefficient is fixed here before the dress run.

## 5. Trigger and admission
Trigger threshold for each seed is the 99th percentile of 999 block-permuted versions of the learner's own B0 training residual, using the validated R5 statistic. Pure-noise traces are retained as a diagnostic.

A guided candidate is admitted only if all three R6 conditions pass:

1. novelty: training `R^2(candidate | complete L0 span including actions) <= 0.50`;
2. validation gain: relative B0 validation RMSE improvement `>= 0.05`;
3. independent challenge: fresh trace from the **same latent world parameters** with action amplitude `1.6`, block-permutation `p <= 0.01` using 999 permutations.

Residual evidence proposes; intervention evidence verifies.

For Null, the challenge is a fresh Null trace. For corrupted controls, a fresh same-meta base trace is generated and its `y` is independently circularly shifted relative to `x/actions` before challenge, preserving its marginal but keeping the mechanism destroyed. The uncorrupted mechanism is never restored for a corruption-control admission test.

## 6. Matched controls (R8)
- `B2a`: random composition candidates + residual-correlation selection.
- `B2b`: the same random candidate bank + validation-only selection.
- `B3-shuffled`: always executes the search budget regardless of trigger state; residual semantics are block-shuffled before guided selection.

B2a/B2b use the same random bank and grammar as each other; guided/B3 use the same grammar and candidate budget. All downstream arms use the same admission criteria when an admission decision is needed.

## 7. Test metrics
Let `E0_s`, `E1_s`, and `EL_s` be B0, oracle B1, and admitted-guided test RMSE for eligible seed `s`. If guided has no admitted feature, `EL_s=E0_s`.

### 7.1 Pooled gap closure
Use ratio-of-sums, never mean of seed ratios:

`G = sum_s(E0_s - EL_s) / sum_s(E0_s - E1_s)`.

95% CIs are percentile seed-level bootstraps with 10,000 resamples of eligible seeds. Circular and RankInteraction are pooled for the primary gate; family-wise values are mandatory diagnostics.

### 7.2 False acceptance
For Null, corrupt-Circular, and corrupt-RankInteraction separately, report the acceptance proportion and the exact one-sided 95% Clopper-Pearson upper confidence bound. The primary safety gate is family-wise, not pooled.

### 7.3 Transfer
The accepted program structure and fitted constants from the source world are held fixed. On an independent same-meta trace with action amplitude `1.6`, only the scalar linear extension coefficient is re-estimated from transfer training data; program structure/constants are **not** retuned. Transfer is evaluated on the transfer test split against the transfer oracle B1.

Transfer pooled gap closure uses the same ratio-of-sums formula and seed bootstrap as §7.1.

### 7.4 In-model ablation
For each admitted guided model, keep all fitted model parameters fixed and block-permute only the extension feature over test-time blocks; do not refit. Let `EA_s` be the resulting ablated test RMSE.

The primary normalized ablation-damage ratio is

`A = sum_s(EA_s - EL_s) / sum_s(E0_s - EL_s)`

on eligible seeds with positive guided test improvement. Seed-level bootstrap gives a 95% CI. This measures how much of the observed guided improvement is destroyed when the fitted extension is temporally broken inside the model.

### 7.5 In-world functional similarity and predictive substitutability
For admitted guided features on non-null worlds:

- functional similarity = `|corr(candidate_feature, hidden_oracle_feature)|` on the untouched world test trace;
- predictive substitutability = `|corr(beta_L*candidate_feature, beta_oracle*hidden_oracle_feature)|` on the same test trace.

Report medians across admitted eligible seeds and family-wise diagnostics.

### 7.6 Matched-search advantage
For B2a and B2b, compute each control's pooled gap closure on exactly the same eligible seeds and define paired differences:

`Delta_a = G_guided - G_B2a`

`Delta_b = G_guided - G_B2b`.

Bootstrap seeds jointly, recomputing both ratio-of-sums values in every resample. Report 95% CIs for each difference.

## 8. H1 gates — all required
H1 PASS requires every gate below:

1. **Null false acceptance:** point rate `<=0.05` and one-sided 95% Clopper-Pearson upper bound `<=0.15`.
2. **corrupt-Circular false acceptance:** point rate `<=0.05` and CP upper `<=0.15`.
3. **corrupt-RankInteraction false acceptance:** point rate `<=0.05` and CP upper `<=0.15`.
4. **Useful gap closure:** pooled `G >=0.35` and 95% bootstrap lower bound `>=0.25`.
5. **Transfer:** pooled transfer gap closure `>=0.25` and 95% bootstrap lower bound `>=0.15`.
6. **In-model ablation:** normalized damage `A >=0.20` and 95% bootstrap lower bound `>=0.10`.

Pure-noise trigger/acceptance behavior, eligible-seed counts, family-wise gap closure, novelty R2, validation gains, challenge p-values, and B3 results are mandatory diagnostics but do not replace any gate above.

## 9. H2 gates — evaluate only if H1 passes
H2 PASS requires every gate below:

1. **In-world functional similarity:** median `>=0.90` across admitted eligible non-null seeds.
2. **Predictive substitutability:** median `>=0.90` across the same seeds.
3. **Guided vs B2a:** `Delta_a >=0.10` and 95% bootstrap lower bound `>=0.05`.
4. **Guided vs B2b:** `Delta_b >=0.10` and 95% bootstrap lower bound `>=0.05`.
5. **MDL constants charged:** every guided candidate score and report uses `0.5` per learned constant; any run with uncharged learned constants is invalid, not a failure/pass.

If H1 fails, H2 is recorded as `NOT_EVALUATED_CONDITIONAL_H1_FAIL`; H2 must not be rescued by inspecting operator similarity.

## 10. DEV margin required before any later frozen run
This Step 3 does not authorize or execute a frozen run. A later frozen run would be *eligible for consideration* only if H1 passes and additionally clears all H1 gates with the following fixed DEV margin:

- zero false accepts (`0/32`) in each of Null, corrupt-Circular, corrupt-RankInteraction;
- pooled gap closure `>=0.40`, CI lower `>=0.30`;
- transfer `>=0.30`, CI lower `>=0.20`;
- ablation `>=0.25`, CI lower `>=0.15`.

Failing this margin means no frozen-run authorization even if ordinary H1 PASS is achieved.
